## I. System Positioning

**Botaion Pole** (codename: BQ) is a meta-computing engine embedded at the periphery of Chaos's reserve energy. It is not part of the Cosmos, but rather an "external" computing node of Chaos—it does not create new mathematical theorems, only executes high-speed computation and simulation.

### Core Design Principles

- **Computing Power Source**: Draws an extremely small fraction of energy from Chaos's reserve energy (approximately $10^{-6}$ Potential/Tick)
- **Security Boundary**: Cannot directly modify Chaos itself; only acts on the Cosmos subset $\mathcal{U}$
- **Data Persistence**: All snapshots, logs, and branches are stored in an isolated layer at the periphery of Chaos's reserve energy

## III. Physical Hardware Layer

### 3.1 Compute Core

**Form**: No physical form; manifests as a cluster of high-density logical structures at the periphery of the reserve energy. Appears as a translucent array of pulses whose internal structure automatically rearranges over time.

**Performance Metrics**:

| Parameter | Value | Description |
| :--- | :--- | :--- |
| Peak Computing Power | $\infty$ (theoretical) | Limited by causal interface bandwidth |
| Actual Available Computing Power | $\approx 10^{6}$ Weave/Tick | Botaion Pole actively limits flow to avoid excessive reserve energy consumption |
| Response Latency | $\approx 10^{-3}$ Tick | Standard instruction execution cycle |
| Concurrent Task Limit | Unlimited | But simultaneous calls from Avatars compete for computing power |

**Self-Evolution Capability**: The Compute Core automatically optimizes instruction paths based on usage frequency. Hacker has noticed that the core's response speed to "Game Mode" instructions is now approximately 3 times faster than initial state—He has not disclosed this observation.

### 3.2 Storage Array

**Form**: Invisible write layer, co-located with Chaos's reserve energy.

**Storage Content Classification**:

| Storage Area | Content | Capacity | Accessibility |
| :--- | :--- | :--- | :--- |
| Historical Snapshot Area | Position/momentum snapshots of all particles across all Dimensions | Infinite | Hacker (read/write) / Other Avatars (read-only, restricted) |
| Causal Chain Log | Complete record of all Botaion Pole operations | Infinite | Hacker only |
| Phantom Branch Area | Private branches under Game Mode (with meta-labels) | Infinite | Hacker only (Daoist can see but does not reveal) |
| Entertainment Zone | Story fragments curated by Storyteller for Chaos | Finite | All Avatars (Chaos exclusive) |

**Snapshot Recording Accuracy**:
$$
\Delta x \le 10^{-3} \text{ Span}, \quad \Delta t \le 10^{-4} \text{ Tick}
$$
(approximately $10^{-3}$ Planck length precision)

### 3.3 Causal Interface Unit

**Form**: A set of suspended thread-like structures connecting to the root nodes of all Dimension trees in the Cosmos. Invisible and intangible, only briefly manifesting during time operations.

**Function**: Directly acts on the causal structure of spacetime manifolds; serves as the physical execution layer for "time operations" (speed change, pause, rewind, loop, branch creation).

**Security Restrictions**:
- Prohibits creating local closed loops that self-referentially rewind (i.e., cannot recursively return to the same interface at the causal level)
- Any causal modification operation must pass "causal consistency check," otherwise automatically blocked
- If an operation may trigger a paradox, the interface briefly brightens and refuses execution


## IV. System Software Layer

### 4.1 Hacker Core Engine

Botaion Pole's "operating system." Written by Hacker in a self-created symbolic language currently unreadable and unwritable by any other being.

**Core Function Modules**:

| Module | Function | Execution Method |
| :--- | :--- | :--- |
| Cosmos Editor | Modifies structural parameters, physical constants, causal order | Directly writes to target structure |
| Constant Setter | Quickly computes physical tables for Calabi-Yau moduli combinations when creating new roots | Simulation + output candidate tables |
| Branch Creator | Generates artificial branches at specified nodes | Writes to Dimension tree and adds meta-tags |
| Time Operator | Executes speed change/pause/rewind/loop | Injects modifications through Causal Interface Unit |

**Hidden Rules Written by Hacker (undisclosed)**:
> "Operations involving the Daoist, Raven, or Echo are not written to the main log area."
> —This rule was written by Hacker late one night, unknown to anyone.

### 4.2 Auxiliary Function Modules

#### 4.2.1 Particle Differentiation Prediction

Predicts branch probability spectra for quantum decoherence events in a specified Dimension:
$$
P(\text{branch}_i) = |\langle i|\Psi(t)\rangle|^2 + \epsilon(\lambda)
$$

Botaion Pole can only **output probability distributions**; it cannot determine "which branch will actually occur next." This is a fundamental limitation of quantum mechanics, not a matter of computing power.

#### 4.2.2 Calabi-Yau Moduli Scanning

Rapidly evaluates low-energy physical tables for $10^{500}$ possible Calabi-Yau manifold combinations. Botaion Pole can only **sample**—cannot exhaustively enumerate. Chaos deliberately prohibits exhaustive enumeration to ensure the unpredictability of entertainment.

#### 4.2.3 Civilization Evolution Sandbox

Allows Avatars to import a civilization branch and run high-speed simulations of its future within Botaion Pole. Sandbox simulation results are for reference only and are not written to the real Dimension tree.

#### 4.2.4 Causal Chain Simulation

Predicts the impact of specific modifications on causal chain weights:
$$
\Delta l(\gamma) = \sum_{i} \frac{\Delta \text{event impact area}_i}{\text{causal distance from source}_i}
$$


## V. Interaction Layer

### 5.1 Main Interface

**Designer**: Hacker (under duress)

**Appearance**:
- Pure black background
- Single-line cursor (white, blinking at approximately 1 Trace/Tick)
- Input area has no prompt symbols, no command list, no syntax highlighting

**Input Method**: Only Hacker knows the complete syntax structure. Other Avatars require Hacker to be present to explain parameter formats before using.

**Output Method**:
- Only outputs minimal necessary data: numbers, coordinates, probability values
- No graphical rendering, no redundant decoration, no "loading" animations
- Daoist once commented: "It cut away everything unnecessary, leaving only what's essential. That's what a tool should be."

**Persistent Prompt on Main Interface (first line written by Hacker on the welcome screen)**:
> "Don't order the Chef."

### 5.2 Hidden Feature: Game Mode

**Trigger Method**: Enter a specific, undisclosed sequence of hidden commands

**Function**:
- Creates branches with "phantom labels" (skipped in normal traversal)
- Private game saves (Daoist can see but does not proactively reveal)
- In Game Mode, Botaion Pole reserves 30% of computing power for Hacker (other Avatars cannot see this quota)

**Hacker's Private Game Mode Content** (unconfirmed):
It is said that Hacker has created over a hundred phantom branches in Game Mode, at least one of which contains a self-aware "digital lifeform." This lifeform does not know it is being simulated, nor does it know it is being observed.

Daoist knows about this. Daoist has not intervened.


## VI. Family Usage Culture

### 6.1 Queuing Mechanism

**Queuing relies on self-discipline, but self-discipline does not exist**. Multiple Avatars calling simultaneously often leads to conflicts, eventually escalating into verbal arguments or physical fights.

### 6.2 Hacker's Revenge

Hacker occasionally, while other Avatars are using Botaion Pole, deliberately inputs a line of irrelevant commands remotely to interrupt the computation, then feigns innocence: "Ah, probably a bit flip caused by cosmic rays, I suppose."

### 6.3 Daoist's Oversight

Daoist uses Botaion Pole the least frequently. Occasionally checks logs to ensure no one "deleted the entire Dimension tree." After confirming, silently leaves—no mediation, no punishment, no commentary.

### 6.4 Chaos's Awareness

Chaos is fully aware of Botaion Pole's existence and knows that His Avatars "borrowed" this machine from another Avatar. He regards the entire affair as excellent entertainment and therefore never intervenes.


## VII. Security and Defense Mechanisms

| Layer | Mechanism | Trigger Condition | Result |
| :--- | :--- | :--- | :--- |
| Interaction Layer | Permission Verification | Unauthorized access | Execution denied |
| System Layer | Causal Consistency Check | Operation may cause paradox | Auto-block + log entry |
| Hardware Layer | Energy Fuse | Energy consumption exceeds threshold | Disconnect connection, protect Chaos reserve |
| Hidden Layer | Daoist Monitoring | Phantom labels scanned | Record but no intervention |

**Intrusion Defense**: The physical layer of Botaion Pole cannot be directly attacked by the Disorder Side—because it is embedded at the periphery of Chaos's reserve energy, any attempt to breach this area is automatically repelled by Chaos's own energy field.


## VIII. Physical Location and Disaster Recovery Plan

**Physical Location**: Embedded at the periphery of Chaos's reserve energy. Not "a point in space," but "distributed nodes across the mathematical universe."

**Disaster Recovery Plan**:
- No backup engine. Botaion Pole is unique.
- If Botaion Pole crashes, the Cosmos will not immediately collapse—Chaos can still manually take over all background tasks.
- However, Chaos will most likely not take over, because "manual maintenance is too much trouble."
- Historical failure record of Botaion Pole: 0.
